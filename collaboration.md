# Contributing to postgres-viz

When opening an issue or pull request, list any AI models you used to prepare the contribution. This includes help investigating a bug, writing code or tests, or drafting the report. If you used several models, list each one. If you know the tool but the model was hidden, write something like `GitHub Copilot (model unknown)`. If you used no AI, write `None`.

For a bug report, describe what you expected and what happened. Include the smallest SQL example or sequence of steps that reproduces the problem, along with your postgres-viz and PostgreSQL versions when relevant. For a feature request, describe the task you want to accomplish.

For a pull request, explain what changed, why, and how you verified it. The [development guide](README.md#development) lists the local checks.
